# Platforms/STM32H743 — CubeMX-проект (ST7735 160×80)

Использование, сборка и настройки платы — `README.md` рядом; здесь —
правила изменения. Тулчейн `cmake/starm-clang.cmake` (ST clang 21.1.1,
`-Oz -g0`); базлайны — `docs/metrics.md`.

## Память — не двигать без обсуждения

- Стек в DTCM: `_estack = ORIGIN(DTCMRAM) + LENGTH(DTCMRAM)` = 0x20020000
  (`.ld`, вектор entry0 не трогался) — `GameT` (5 608 Б) растёт вниз из
  DTCM, весь CPU-only сим-путь 0 WS.
- MPU region 2 (DTCM): Normal non-cacheable non-shareable (TEX1), XN —
  не Device (по-канону: спекуляция/упорядочивание).
- `_heap_end = конец AXI RAM` (`sysmem.c`): с переездом стека `_estack`
  больше не граница кучи — любой malloc без этого фикса навсегда давал бы
  ENOMEM. malloc по-прежнему никто не зовёт (`_sbrk` выкидывается
  `--gc-sections`).
- DMA-секции держать в RAM/AXI: DMA в DTCM не достанет.
- Контроль после регена: `_estack 0x20020000`, `_heap_end 0x24080000`,
  ICache inline в дизмазме `main`.
- Отложено: «всё в TCM» (код ~22 КБ < ITCM 64 КБ, данные ~6 КБ < DTCM 128
  КБ) — цена: кастомный `.ld` вне Cube-шаблона + копия кода в старте.

## Реген-факты (Cube 6.18.1, пункт N бэклога)

- `.ld` регенится только в границах MEMORY/MX-маркеров — пользовательские
  строки (`_estack`, `_heap_end`) пережили реген.
- Ловушка MMT: правка региона в Memory Mapper переименовывает DTCM-строку
  в дефолт `RAM_DTCM0` — имя `DTCMRAM` возвращать вручную (слишком ранний
  обратный шаг ломает `_estack = ORIGIN(DTCMRAM)`).
- Свежие имена секций `.ld` — `.RAM_D1dtcram` и т.п.: будущие DMA-секции
  использовать с ними, не со старыми `.RAM_D1`.
- Реген пересоздаёт `main.c`-скелет — сносить; `main.cpp`/`sysmem.c` не
  трогает; массовая EOL-перемешка HAL/CMSIS в git после регена — норма,
  нормализуется при коммите.
