# Platforms/Host — хост-платформа ядра (окно-зритель, дампы)

Та же точка инстанциации, что и MCU-платформы: `GameT<SimLcd<W,H>>`
над framebuffer-панелями 240×240 (форма F401) и 160×80 (форма H743,
кроп карты) — теми же заголовками ядра и тем же `assets.cpp`, без HAL.
Назначение — видеть ядро глазами: живое окно, кадры, дифы до/после
правок. Windows, mingw g++ (подходит clang); никаких внешних
зависимостей.

## Состав

- `sim_lcd.hpp` — `SimLcd<W,H>`: панель под concept `Disp`. Статический
  `print` копирует RGB565 в fb с обратным байтовым свопом (ассеты
  хранятся в панельном порядке — «первый байт потока = старший полубайт
  пикселя», см. комментарий в assets.cpp); fb держит «истинное» слово.
  Завёрнутые за ноль координаты не рисуют (трипваер `clipped`: 0 =
  контракт BLOCK держится).
- `png.hpp` — минимал-райтер PNG (stored-deflate + adler, без zlib).
- `main.cpp` → `host_view.exe` — batch-дампы: PNG-серия (кадр f0000 =
  чистая карта после init), contact-sheet серии, GIF-анимация прогона
  (свой LZW-энкодер). CLI: `[240|160|all] [frames] [seed] [every]
  [scale] [gif_delay] [outdir]`; seed фиксирует rand → битва
  воспроизводима; GIF = init + до 480 кадров, `gif_delay=0` выключает.
- `live.cpp` → `host_view_live.exe` — окно-зритель (чистый WinAPI:
  таймер ~15 мс = темп кадра, StretchDIBits fb → клиент). Соло-режим
  воспроизводит batch-битву покадрово (проверено попиксельно); в `all`
  обе игры делят один rand-поток. Ключи: Space пауза / S шаг /
  +− скорость / R рестарт / N новый сид / P дамп PNG / Esc выход.
  `[autoframes]` — самотест (автостоп с дампом).
- `wingrab.cpp` → `wingrab.exe` — PrintWindow клиентской области
  живого окна в PNG (BGRA→RGB565, старшие биты каналов; после
  DeleteObject биты DIB не читать).
- `gif_check.py`, `pngdiff.py` — независимые проверялки: первый
  попиксельно сверяет GIF с PNG-серией, второй — диф двух дампов
  (count, bbox, первый пиксель) — главный инструмент «как ядро
  изменилось».

## Сборка

- `cmake -S . -B build -G Ninja && cmake --build build` (см.
  `CMakeLists.txt`); либо прямые g++-строки в шапках исходников.
- `-static` обязателен: чужой `libstdc++-6.dll` в PATH ловит
  STATUS_ENTRYPOINT_NOT_FOUND.
- В CMake-цели `Game_Core` не заворачивать: цель `display` тянет
  `stm32cubemx` (HAL-заголовки) — `assets.cpp` компилируется напрямую
  с тремя include-путями ядра.
- Дампы пишутся в `out/` (gitignore-нут); один `loop()` = один кадр —
  пейсер HAL_Delay единственное, чего нет на хосте.

## Проверки

- GIF: чистая пара «ширина растёт, когда присваиваемый код перестаёт
  влезать» × декодер «eq» (len == 2^size) — единственная согласованная,
  подтверждена `gif_check.py` против PNG-серии (26 кадров, включая
  CLEAR на переполнении словаря) и GDI+.
- Live vs batch: кадр из окна == кадр batch при том же сиде.

## Ловушки окружения

- Запуск окна из агентских shell-вызовов: job-объект с kill-on-close
  убивает процесс с окончанием вызова — постоянный запуск только через
  WMI (`Invoke-CimMethod Win32_Process Create`) или руками пользователя.
- Декодер-проверки хранят слоты clear/eoi таблицы LZW после CLEAR —
  иначе индексы съезжают на 2 (грабли `gif_check.py`).
