# Platforms/Host — хост-платформа ядра (правила изменения)

Та же точка инстанциации, что и MCU-платформы: `GameT<SimLcd<W,H>>`
над framebuffer-панелями 240×240 (форма F401) и 160×80 (форма H743,
кроп карты) — теми же заголовками ядра и тем же `assets.cpp`, без HAL.
Использование (сборка, инструменты, ключи) — `README.md` рядом; здесь —
правила изменения.

## Внутренности

- `sim_lcd.hpp` — `SimLcd<W,H>`: панель под concept `Disp`. Статический
  `print` копирует RGB565 в fb с обратным байтовым свопом (ассеты
  хранятся в панельном порядке — «первый байт потока = старший полубайт
  пикселя», см. комментарий в assets.cpp); fb держит «истинное» слово.
  Завёрнутые за ноль координаты не рисуют (трипваер `clipped`: 0 =
  контракт BLOCK держится).
- `png.hpp` — минимал-райтер PNG (stored-deflate + adler, без zlib).
- В CMake-цели `Game_Core` не заворачивать: цель `display` тянет
  `stm32cubemx` (HAL-заголовки) — `assets.cpp` компилируется напрямую
  с тремя include-путями ядра.
- Один `loop()` = один кадр — пейсер HAL_Delay единственное, чего нет
  на хосте.

## Проверки

- GIF: чистая пара «ширина растёт, когда присваиваемый код перестаёт
  влезать» × декодер «eq» (len == 2^size) — единственная согласованная,
  подтверждена `gif_check.py` против PNG-серии (26 кадров, включая
  CLEAR на переполнении словаря). Декодер-проверки хранят слоты
  clear/eoi таблицы LZW после CLEAR — иначе индексы съезжают на 2.
- Live vs batch: кадр из окна == кадр batch при том же сиде.
- Golden-гейт: фиксированный прогон попиксельно против `golden/` —
  обновление эталона только осознанно (`--rebaseline` + коммит
  с объяснением); механика — `golden_check.py`.

## Ловушки окружения

- Запуск окна из агентских shell-вызовов: job-объект с kill-on-close
  убивает процесс с окончанием вызова — постоянный запуск только через
  WMI (`Invoke-CimMethod Win32_Process Create`) или руками пользователя.
