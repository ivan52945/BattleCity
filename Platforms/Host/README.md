# Platforms/Host — хост-платформа (зритель и дампы)

Пользование: сборка и средства просмотра. Правила изменения и
ловушки окружения — `AGENTS.md` рядом.

## Назначение

Исполнение ядра на ПК без целевой платы: та же точка инстанциации, что
и у MCU-платформ — `GameT<SimLcd<W,H>>` над framebuffer-панелями обеих форм
(240×240 — форма F401, 160×80 — форма H743 с кропом карты), те же
заголовки ядра и тот же `assets.cpp`. Windows, mingw g++; внешних
зависимостей нет.

## Сборка

```
cmake -S . -B build -G Ninja && cmake --build build
```

- `-static` обязателен: посторонний `libstdc++-6.dll` в PATH вызывает
  STATUS_ENTRYPOINT_NOT_FOUND.
- Дампы пишутся в `out/` (каталог в gitignore).

## Инструменты

| Инструмент | Что делает |
|---|---|
| `host_view.exe` | пакетные дампы: PNG-серия, contact-sheet, GIF-анимация прогона |
| `host_view_live.exe` | живое окно: таймер ~15 мс = темп кадра, StretchDIBits fb → клиент |
| `wingrab.exe` | PrintWindow живого окна → PNG (BGRA→RGB565) |
| `gif_check.py` | попиксельная сверка GIF с PNG-серией |
| `pngdiff.py` | сравнение двух дампов (count, bbox, первый пиксель) — главный инструмент «как ядро изменилось» |

Аргументы пакетного режима (`host_view.exe`): `[240|160|all] [frames]
[seed] [every] [scale] [gif_delay] [outdir]`; сид фиксирует rand —
битва воспроизводима; `gif_delay=0` выключает GIF.

Ключи живого окна: Space пауза / S шаг / +− скорость / R рестарт /
N новый сид / P дамп PNG / Esc выход; `[autoframes]` — самотест
(автостоп с дампом).

## Предупреждения при использовании

- Соло-режим живого окна воспроизводит пакетную битву покадрово
  (проверено попиксельно); в `all` обе игры делят один rand-поток.
- После `DeleteObject` память DIB у `wingrab` недействительна — не
  читать.
