# ADR-0009 — Host-юнит-тесты: контракт-оракул, doctest, мутационная проверка

Статус: принято. Дата: 2026-11-11 (сетка `Game_Core/Tests/`, пилот — пул
`Lobby`).

## Контекст

Регрессия ядра держалась на двух опорах: compile-time `static_assert` и
host-тест `tmp/host_test/` (дым: инстанциация + пара кадров + счётчики
blit'ов, вне git сознательно). Ядро платформенно-независимо и уже
собирается на хосте теми же заголовками — но поведенческой сетки у
модулей не было. MCU-платформы (CubeMX + header-драйверы) в юнит-тесты
не входят: драйверы ломаются громко (экран), их уровень — визуальная
проверка и host-зритель.

## Решение

- **Юнит = инстанциация.** Единица тестирования — конкретная
  инстанциация шаблона (`Lobby<Node,4>`, `GameT<FakeLcd>`), граница —
  публичный API заголовка. Подмены — только через существующие швы
  (template-параметры, concept `Disp`): никаких `#ifdef TEST`,
  виртуальных интерфейсов и тестовых копий кода — иначе ломаются
  ADR-0004 и метрики.
- **Оракул = контракт.** Кейсы выводятся из README модуля (техники
  чёрного ящика: эквивалентное разбиение, краевые значения, переходы
  состояний, таблицы решений) с трассировкой «кейс → пункт контракта».
  Тест, выведенный из кода, может только повторить код; тест из
  контракта проверяет обещание. Если контракт не отвечает — сначала
  дополняется README, потом пишется кейс.
- **Два режима.** Существующий код: контракт → кейсы → мутационная
  проверка (реализация ломается точечно; каждый мутант обязан быть
  пойман, выживший мутант = дыра в сетке). Новый код: test-first
  (red-green-refactor). Мутационная проверка заменяет погоню за
  coverage: покрытие — индикатор, а не цель.
- **doctest, vendored.** Один header в `Tests/doctest/`, ноль внешних
  зависимостей — в стиле проекта. GoogleTest/Catch2/Unity отклонены:
  тянут клон/сборку либо заточены под C и link-time швы, которые ядру
  не нужны — оно и так компилируется на хосте целиком.
- **Сборка.** `Tests/` — standalone CMake-проект (платформенные пресеты
  не задевает); POST_BUILD-хук гоняет тесты после каждой сборки —
  упавший кейс роняет сборку; ctest — точечный прогон и будущий CI
  (пункт T бэклога). Статическая линковка против чужого
  `libstdc++.dll` (ловушка Host). Санитайзеры — опция
  `TESTS_SANITIZERS`: у mingw-w64 libasan нет; на тулчейне с ним —
  включать (краевой мутант `>= → >` читает `items[N]`).

## Последствия

- Пилот `Lobby`: 20 кейсов / 87 проверок; мутанты `>= → >`, «без
  swap», «без флага `is_sleep`» пойманы целевыми кейсами.
- Процесс вскрыл дыры контракта: «резервы не накапливаются» и «`lull()`
  на пустом окне — на вызывающем» дописаны в `Utils/README.md` —
  контракт дорабатывается там, где тесты его вскрыли.
- Каждый новый модуль ядра получает сетку в `Tests/` по рецепту из
  карточки; политика процесса — раздел «Тесты» корневой карточки.
