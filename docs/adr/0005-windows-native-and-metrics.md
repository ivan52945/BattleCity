# ADR-0005 — Windows-native сборка на CubeCLT + методика замеров

Статус: принято. Дата: ≈2026-11-06 (логи сборок вне репозитория).

## Контекст

Сборка исторически жила в WSL; цифры замеров надо снимать нативно и
повторяемо, без ручного «примерно по коду».

## Решение

- **Инфраструктура:** CubeCLT 1.22.0 (`C:\ST\STM32CubeCLT_1.22.0`); PATH уже
  указывает на его тулчейны (`starm-clang\bin`, `Ninja\bin`, `CMake\bin`,
  `GNU-tools-for-STM32\bin`). `cmake --preset Release` + `--build --preset
  Release` в каталоге платформы; тулчейн-файлы резолвят компилятор по имени
  из PATH. WSL-зависимость снята: H743 Release нативно байт-в-байт с
  wsl-release (31 480 / 1 904 на тогдашнем дереве), F401 — 29 600 / 2 272.
- **Методика замеров:**
  - FLASH/RAM — `--print-memory-usage` (включён в линкер), разложение —
    `objdump -h`.
  - Стек — SP-срез: HW-break на входе `GameT::loop` (адрес из свежего .map),
    использование = `_estack − SP` (GameT + Lcd + локалы main).
  - Такты — DWT-цикломер: `DEMCR TRCENA`, `DWT_LAR 0xC5ACCE55`,
    `DWT_CTRL CYCCNT`; пара точек «вход `loop`» → «`HAL_Delay` pacer'а main»;
    повторяемость ±0.1% на 3 кадрах, первый кадр после reset стрижётся.
  - `sizeof` — size-пробой-канарейки (`tmp/size_probe.cpp`) + `starm-nm`
    (стARM-clang 21.1.1).
  - Символы — `starm-nm` из Release-ELF (доля libc-функций во flash).

## Последствия

- Все контрольные точки повторяемы на Windows; логи сборок — вне
  репозитория (`%TEMP%\opencode\build_*.log`).
- Методика применялась во всех последующих ADR (0006–0008).
- Историческая «хроника» размеров считается преждевременными замерами —
  актуальные базлайны живут в `docs/metrics.md`.
