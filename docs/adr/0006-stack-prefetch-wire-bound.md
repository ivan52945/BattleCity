# ADR-0006 — Стек, prefetch и вывод «петля wire-bound»

Статус: принято. Дата: ≈2026-11-07…08 (коммиты `2e4f7fb`, `380eecb`,
`95bafa0`, `be21c4d`; боевые замеры F401).

## Контекст

F401: `._user_heap_stack` (0x400 резерв) лжив против фактического расхода
5 360 Б — рост стека мог «молча» не попасть в RAM-печать линкера.
Параллельный вопрос — «что ускоряет кадр» (ожидания от prefetch, SPI 16
бит, девиртуализации).

## Решение

- **Q — честный стек-резерв:** StackSize поправлен в CubeMX (0x400 →
  `0x1800`) и реген проложен; `._user_heap_stack` = 0x1A04 ≥ факта;
  столкновение больше не может пройти «молча». RAM-печать F401: 2 272 →
  7 392 (честная). Heap 0x200 оставлен (512 Б из 64 КБ — микроскоп).
- **A3 — value-init таблиц драйверов:** `{ INV_COL, 0 }`/`{ NORM_ON, 0 }`
  → `{ CMD, 0, {} }` (`st7735.hpp`, `st7789.hpp`) — инвариант таблиц
  выписан явно; после этого `-Wextra -Wshadow` по ядру чисты.
- **A4 — снят write-only `GameT::game_i`** (счётчик кадров без читателей):
  H743 −32 Б flash, F401 const.
- **C9 — flash prefetch** в `main.cpp` USER CODE Init (F401): строка
  правильная (boot/fetch-heavy зоны), но **на кадр не влияет** — A/B на
  живом ядре (гашение `FLASH->ACR bit8` через gdb): дельта 0.12–0.78% —
  за шум.
- **Вывод wire-bound:** модель подтверждена обеими платформами —
  H743 765 µs (60 Мбит, non-wire ≈ 0.3 мс) / F401 1 150 µs (42 Мбит,
  non-wire ≈ 0.4 мс) = wire-time + небольшой non-wire хвост. Шина, не CPU,
  — бутылочное горло; «SPI 8→16» контро-пунктом закрыт.

## Последствия

- Контро-пункты закреплены в `docs/metrics.md` (CPU-ре-архитектуры «не
  сейчас»; prefetch — гигиена; SPI 16 бит — не делать).
- Реген-цикл CubeMX отработал по расписанию пункта N (см. H743-карточку).
- Фактический SP-расход F401 на живой плате — 5 368 Б (SP-срез, ADR-0005).
