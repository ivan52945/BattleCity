# ADR-0001 — Классовая переработка ядра: Disp_Iface, поля disp, спрайты в flash

Статус: принято. Дата: ≈2026-11-02 (бэкап `BattleCity_2026-11-02.7z`).

## Контекст

Ядро было C-функциями с прокладкой `Display/display.*`; у `Game`/`Entity`
дисплей жил статическим полем — несколько игр на разных панелях были
невозможны; спрайты лежали в RAM; таблица спавна была хардкодом.

## Решение

- Переезд на классы: драйвер реализует `Disp_Iface`; объект создаёт
  `main()` и инжектирует `Game(Disp_Iface*)`.
- Дисплей: статические поля → члены (штамп один раз из `Game::init()` через
  `Lobby::set_disp()` — пул переиспользует слоты, реконструкции нет, одного
  штампа хватает на жизнь). Цена: +4 Б × 116 слотов ≈ +464 Б RAM (на стеке).
- Спрайты в flash: все 4 массива `assets.cpp` стали const — **−6 016 Б RAM**,
  +~376 Б flash; DMA читает flash напрямую — штатно на F4.
- Спавн: линейный расчёт от реального поля (`cfg::spawn_margin_px`,
  `spawn_slots`, `units_per_side`), `is_booked(point_t, Tank)`, `abs(int)`
  вместо `fabs` (на F4 double — soft-emulated, `abs(int)` — один `rsbs`);
  хардкод `tank_spawns` удалён, `config.hpp` — только ручки.
- Идиомы: XOR-swap → `std::swap` (тактовый паритет, но без хрупкости при
  алиасинге); `st7789_wiring` — designated initializers, опциональные
  CS/RST (поля просто не указываются, guard'ы `if (CS_Port)`).
- Снесены мёртвые файлы: `Display/display.*`, конфиг-макросный `st7789.h`,
  `dir.hpp`, дубликат платформы `Game_Core/Platforms/` (116 файлов).

## Последствия

Многопанельность на уровне объектов (затем — на уровне типов, ADR-0004);
RAM-экономия от const-спрайтов; спавн стал ручками `cfg::`. Полиморфизм
`Disp_Iface` позже убран целиком (ADR-0004), штамп через `set_disp()` тоже
— каркас классов остался.
