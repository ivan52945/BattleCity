# ADR-0004 — Typed-Game: цепочка шаблонов, vtable умерла конструкцией

Статус: принято. Дата: ≈2026-11-04…05 (дампы в `tmp/template_exp/`).
Коммиты: `7ce243f` (этап 2), `cfa03a9` (этап 3), `c4e7459` (этап 4),
`93c0ba9`, `60cc047`, `8e47534` (триаж).

## Контекст

Полиморфизм `Disp_Iface` (ADR-0001) оставлял vtable-записи и слотовые
указатели дисплея. LTO-надежда снята замером (ADR-0002). Пункт L — «типизированная
Game: полное удаление vtable-записей».

## Решение

- **Этап 2 — типизация цепочки:** `GameT<LcdT>` → `Lobby<Tank<LcdT>>` /
  `<Shell<LcdT>>` → `Entity<LcdT>`; blit — прямые вызовы членов финального
  класса (не девиртуализация — отсутствие dispatch-записей по построению).
  Инстанс в `main.cpp`: `using Lc = ST7789<...>`; multi-панельность
  сохранена на уровне типов. Члены зависимой базы переэкспортированы
  `using` (без `this->`-бури). .cpp ядра удалены, `assets.cpp` —
  единственный TU.
- **Этап 3 — static blit + concept `Disp`:** `print_img` и вся транзакционная
  цепочка ниже — static (wiring-NTP, состояния нет); `Entity` зовёт
  `LcdT::print_img(...)` без объекта; `Lobby::set_disp()` удалён, слоты не
  несут `LcdT*` (**−4 Б × 116 = −464 Б stack**; это stack-расход, не
  .bss/.data). `GameT` держит одну ссылку `disp` для lifecycle.
  **noinline-инвариант `print_img`**: иначе тело SetWindow+DMA (~300 Б)
  реплицируется в каждый print/clear-сайт (+1–3 КБ flash).
- **Этап 4 — constexpr-геометрия:** `fld_x_end/fld_y_end` = `LcdT::w()/h()−1`;
  лестница спавна — constexpr-таблица (`make_spawn_coords()`): 112 Б в
  .rodata вместо стека объекта; `init()` свёлся к `disp.init()`.
- **Триаж:** идея «EntityBase-сплит» отбита механикой C++ (зависимая база:
  разводка не сокращает using-канализацию; второй прямой базой = ромб,
  virtual base = vptr назад, композиция = переименование каждого доступа).
  Гибридный трим using: правило «импорт только при ≥3 голых сайтах»
  (Tank 6, Shell 3). Деструкторы Tank/Shell сняты — незапускаемы по
  архитектуре (пул живёт значениями в `GameT`, teardown недостижим на MCU;
  тел в flash и так не было).

## Последствия

- F401 FLASH −568 (22 584 → 22 016), H743 −536 (26 992 → 26 456); RAM
  2 272 / 1 904 const. По игровому пути 0 непрямых blx, по бинарнику 0
  vtable-ссылок.
- Host-тест (`tmp/host_test/`) — fake-драйвер удовлетворяет `Disp`,
  инстанцируется теми же заголовками: регресс-сетка для шаблонного ядра.
- Constraint-эхо схлопнуто: `template <class LcdT> requires Disp<LcdT>` ×7
  → `template <Disp LcdT>`.
