## Память-расклад H743 (сессия 08-11, вечер): ICache + стек → DTCM

- [x] **ICache включен** (`main.cpp`, карман `USER CODE Init`): `SCB_EnableICache()` — после `MPU_Config()`/`HAL_Init`, до `SystemClock_Config` (порядок ST AN: кэш после MPU). 16 КБ I-cache: фетч из flash 4 WS → hit 0 WS. Coherency-обязанностей ноль (прошивка неизменяема, DMA кэш не использует). Откат — одна строка `SCB_DisableICache()`. Дизмазм `main()`: inline-тело (проверка бит17 CCR → ICIALLU `str [r0,#0x23c]` → `ccr |= 0x20000`) сидит между `HAL_Init` и `SystemClock_Config`.
- [x] **Стек → DTCM** (`STM32H743xx_FLASH.ld`): `_estack = ORIGIN(DTCMRAM) + LENGTH(DTCMRAM)` = `0x20020000`, `_sstack = 0x2001FC00`; растёт вниз; **`GameT` (5 344 Б) уехал вместе со стеком** — весь CPU-only сим-путь 0 WS. Вектор entry0 — `.word _estack` (startup не правился). Правило замечено в .ld: DMA1/DMA2 в DTCM не достанут — DMA-секции держать в RAM/AXI.
- [x] **`_sbrk` фикс** (`sysmem.c`): лимит кучи = новый символ `_heap_end = ORIGIN(RAM) + LENGTH(RAM)` = `0x24080000` (was `_estack − _Min_Stack_Size`; с переездом `_estack` любой malloc навсегда давал бы ENOMEM — сравнение кучи в AXI с адресом в DTCM). malloc по-прежнему никем не зовется — `--gc-sections` выкидывает `_sbrk` из ELF; при появлении потребителей секция свяжется сама. Схема-забор и NOTE в шапке переписаны под новый расклад.
- [x] **MPU region 2 (DTCM)** выписан самодостаточно: Device_NGNRE (TEX2) → **Normal non-cacheable non-shareable** (TEX1, C=0, B=0), `SubRegionDisable=0`, XN. Device на стеке был легален, но Normal — по-канону (спекуляция/упорядочивание).
- **Цифры (wsl-release, CubeCLT 1.22, st-arm-clang, `-Oz`):** FLASH **31 448 → 31 480** (+32: inline I-cache + выписанный MPU-регион, − упрощенный `_sbrk`; база — свежая пересборка нетронутого дерева: дерево давно ушло от 26 488 старой хроники), **RAM 1904 const**, DTCM/ITCM/SRAM в линкере по-прежнему 0 (стек не линкуется как данные). Символы: `_estack 0x20020000`, `_sstack 0x2001FC00`, `_heap_end 0x24080000`.
- [ ] **На железо — за пользователем:** игра жива; контроль SP в дебаггере ≈ `0x2001FFxx` при первом push; наблюдение, что артфактов/странностей нет (ICache на данные не влияет, переход в DTCM не влияет — но живой тест обязателен по канону).
- **Обсуждение и решения дня:** «всё кроме ассетов в TCM» признано жизнеспособным (код ~22.3 КБ < 64 КБ ITCM, данные ~6 КБ < 128 КБ DTCM) — отложено: ценой кастомный `.ld` вне Cube-шаблона + копия ~22 КБ в старте; лестница осталась: I-cache + DTCM-стек (сделано сейчас), ITCM для горячего кода — по цифрам DWT-зонда. `RAM_D4 LENGTH=64K` в `.ld` — на H743 SRAM4 = 16 КБ (Cube-шаблон от H723-семейства); пусто, правка отложена в связку с будущими `.ld`-работами.

## Контро-пункты — НЕ трогать

- **Стоимость кадра измерена.** DWT-цикломер (сессия замеров): `GameT::loop` = **183 549 ± 0.1% тактов = 765 µs @ 240 МГц = ~4.9% периода кадра** — запас ~19×. Любая ре-архитектура CPU-экономии (девиртуализация, O(n²) → spatial hash и т.п.) начинается «не сейчас» по этой цифре. Старая оценка «resolve_collision ~1% кадра» подтверждалась, новая база — 765 µs.
- **Девиртуализация рефакторингом.** Измеренная цена виртуальности: ~0.03–0.04% кадра (~50–60 blit × ~4 такта). Оверлеер: одна вешь `override final` в `ST7789` уже стоит + возможный LTO. Переписывать структуру ради этого — нет. *Поправка сессии typed-Game:* сделано в формате, который при этом ещё и чистит flash/RAM (полный свод — новый раздел выше); замер по тактам «виртуальность бесплатна» остался верен и не был мотивацией — мотивацией была структура + flash + stack.
- **`resolve_collision` O(n²)** — ~2.5k сравнений/кадр, <1% кадра. Реже трогать.
- **`int → int16_t`** у `Entity` — бас численный выигрыш 2–3 КБ RAM среди ~120 объектов; имеет только если когда-нибудь RAM станет узким местом.
- **HAL busy-wait** (`while (hspi->State != READY)`) — легален: `State` объявлен `__IO` (volatile), при `-O3` не сворачивается.

- **SPI datasize 8 → 16 бит (F401 и вообще) — не делать; шина, не bus, — бутылочное горло.** Wire: APB2 84 МГц, prescaler 2 = **42 Мбит/с** (максимум: минимальный предделитель SPI — 2; панель > 62.5 МГц не тянет). Полуслово не меняет битовый объём ⇒ wire-time нулевой выигрыш. Байтовый DMA дотягивает потолки с запасом 8× (24 нс / байт при потребности 190 нс/байт): TXE-реквест + 2 AHB-транзакции на байт. Пиксельный трафик ≈ 3–4 КБ/кадр → wire-time 0.7 ms — синхронист с измеренным H743 (60 Мбит/с → 765 µs): петли полностью wire-bound. Цена полуслова — пере-разгон `CR2.DS` 8↔16 на каждый print (команды остаются 8-битными) + пересчёт BigDAT-чанков в полуслова + DMA PSIZE/MSIZE — сложность ради bus-overhead, который и так не узкий. Пересмотреть, только если бущий F401 DWT-замер покажет overhead-bound (метод уже готов, см. сессию замеров).
