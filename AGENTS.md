# BattleCity — правила для агента

Портативные «Танчики» на STM32: типизированное C++20-ядро без HAL и без
dispatch-записей (vtable умерла конструкцией, ADR-0004), драйверы дисплея —
header-шаблоны с wiring в non-type параметрах, хардвер и инстанциация — в
платформах. Панели: F401 → ST7789 240×240 (SPI1, 42 Мбит), H743 → ST7735
160×80 (SPI4, 60 Мбит). Кадр wire-bound: время петли — это шина, не CPU.

## Как читать эти документы

Знания расселены по дереву: каждый модуль описывает сам себя в своём
`AGENTS.md` (аналог CMakeLists.txt, но про знания). Открой карточку модуля,
прежде чем менять код в нём. Разделение ролей: карточка — про то, как
модуль менять; `README.md` рядом (где есть) — про то, как модулем
пользоваться (назначение, вход/выход, пример, предупреждения).
Контракт метода — doc-комментарий в его заголовке; README слой
целиком держит и заголовки не повторяет.
История решений — `docs/adr/`, цифры замеров — `docs/metrics.md`, снимок
старого бэклога-летописи — `docs/archive/`.

## Сборка и контроль

- Нативно в Windows на CubeCLT 1.22.0 (st-arm-clang 21.1.1,
  arm-none-eabi-gcc, Ninja, CMake). WSL не нужен (ADR-0005).
- В каталоге платформы: `cmake --preset Release`, затем
  `cmake --build --preset Release`. Артефакт — `build/<пресет>/Tanks_*.elf`.
- `--print-memory-usage` включён в линкер: сверяй FLASH/RAM до/после правки
  (базлайны и контро-пункты — `docs/metrics.md`).
- Регрессия ядра: юнит-тесты `Game_Core/Tests/` (doctest, гоняются
  после каждой сборки; README-контракт → кейсы → мутационная проверка)
  и host-тест `tmp/host_test/` — их инварианты не ослаблять.

## Код

- Комментарии в коде — только на английском языке.

## Тесты

- Ядро тестируется на хосте: юнит = инстанциация над фейк-панелью,
  оракул — контракт модуля (README), не код (ADR-0009).
- Существующий код: контракт → кейсы → мутационная проверка.
  Новый код: test-first (red-green-refactor).
- Тест — только через публичный API: `#ifdef TEST` и тестовых копий
  кода нет; шов — template-параметр (ADR-0004).
- Кейс называет свою мутант-мишень; выживший мутант — дыра в сетке,
  а не норма.

## Коммиты

- Шаблон сообщения — `act: descr`.
- `act` — что было сделано, всегда ровно одно слово из набора: `feat`,
  `fix`, `refactor`, `style`, `docs`. Другие слова не используются.
- `descr` — короткое и по возможности ёмкое описание, только на
  английском языке.
- Один коммит — одна конкретная вещь: добавил фичу `а` — один коммит,
  пофиксил баг `б` — другой, отрефакторил `c` — третий, и так далее.
  Разные действия в один коммит не смешивать (по возможности).
- Нормализация окончаний строк при коммите обязательна: работает
  `* text=auto` из `.gitattributes` (CRLF→LF на уровне блоба при add;
  checkout остаётся на совести окружения — Windows пишет CRLF, WSL
  оставляет LF). Правило не отключать и не обходить; чисто EOL-перемешка
  в диффе (например, после регена CubeMX) — это нормализация отработала
  один раз, дальше диффы идут по контенту.

## Дисциплина платформ (CubeMX)

- `Platforms/*` генерируются CubeMX (`.ioc`): массовые правки — только по
  явному согласию пользователя.
- Рукописные точки: `Core/Src/main.cpp` (main.c-скелет снесён; реген
  пересоздаёт его — сносить), USER CODE-карманы, `.ld` в границах
  MEMORY/MX-маркеров.
- Реген-факты и ловушки — `Platforms/STM32H743/AGENTS.md`.

## Бюджеты

FLASH/RAM/стек — `docs/metrics.md`. Правило: правка ядра не должна ухудшать
базлайн без обсуждения; каждый значимый замер — новая строка в metrics.md.

## Сопровождение этой документации

- Правишь контракт модуля — правь его `AGENTS.md` (и `README.md`, если
  меняется использование) тем же коммитом.
- Карточки — только текущие факты (≤ 60–80 строк), «почему» — в `docs/adr/`,
  цифры — в `docs/metrics.md`.
- Новое решение (выбор альтернативы) — новый ADR; старые задним числом не
  переписывать.
- Не документировать то, что grep находит за пять секунд: писать «почему»,
  а не «что».

## Контро-пункты — не трогать без явного запроса

- Ре-архитектуры ради CPU-экономии: кадр wire-bound (765 µs H743 / 1150 µs
  F401, запас ~19×) — см. metrics.md.
- SPI 8→16 бит — не делать: полслово не меняет битовый объём.
- `resolve_collision` O(n²), `HAL` busy-wait, `int` у Entity — легальны и
  измерены (metrics.md, раздел «Контро-пункты»).
