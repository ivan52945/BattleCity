# DeviceDrivers — дисплейные драйверы

Контракт использования header-драйверов ST7789/ST7735. Правила
изменения — `AGENTS.md` рядом.

## Назначение

Драйвер панели для ядра: header-шаблон, wiring — non-type параметры,
компилятор встраивает константы в тела транзакций. Объект без состояния
(только scratch-буфер: ST7735 320 Б / ST7789 416 Б). Стыковка с ядром —
concept `Disp` (`Display/Inc/disp.hpp`); нарушение формы ловится в
точке инстанциации `GameT`.

За что НЕ отвечает: CS-обрамление кадра (его делает `GameT::loop`),
выбор полосы boot-clear (платформа), шрифты (`fonts.c` — резерв,
не собирается).

## Вход / Выход

- Инстанциация: `using Lcd = ST7789<&hspi1, ...>;` — wiring в
  non-type параметрах: дескриптор SPI (указатель как non-type
  параметр), порты GPIO — целые `GPIOx_BASE` (не `GPIO_TypeDef*`),
  пины, `sizes` (например `st_240x240`), `single_device`, биты
  MADCTL/инверсии.
- Неподключённая линия передаётся как `0`: защитное условие
  вычисляется на компиляции, ветка не генерируется.
- `w()/h()` — constexpr-геометрия панели.
- `init()/select()/unselect()` — жизненный цикл экземпляра: вызывает
  их `GameT` через единственную ссылку.
- `print(x, y, w, h, img)` — статический blit: вызывается без объекта;
  BLOCK-контракт — blit с координатами, завёрнутыми за ноль, не
  выполняется.

## Пример применения

Реальные call-sites: `Platforms/*/Core/Src/main.cpp` (ST7789/SPI1,
ST7735/SPI4), драйвер-двойник (fake) — `tmp/host_test/main.cpp`. Схема:

```cpp
using Lcd = ST7735<&hspi4, /* GPIOx_BASE, пины, размеры... */>;
Lcd lcd;                  // объект без состояния — только scratch-буфер
GameT<Lcd> game(lcd);
game.init();              // init-таблица из flash + boot-clear
```

## Предупреждения при использовании

- Драйвер не переключает CS внутри транзакций — обрамление кадра
  `select()/unselect()` делает `GameT`; blit, выполненный до открытия
  CS-окна, до панели не доходит.
- `single_device` («CS есть, но шина собственная»): `init()` выбирает
  чип прямой записью в GPIO, `select()/unselect()` далее не выполняют
  действий.
- Boot-clear — flash-полосы `disp_clear_240x16`/`disp_clear_160x16`
  (`assets.cpp`); платформа определяет только свою.
- Данные идут DMA из flash напрямую: прошивка неизменяема,
  кэш-обязанностей нет (ADR-0007).
