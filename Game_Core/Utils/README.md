# Utils — пул `Lobby<T, N>`

Контракт использования пула из `Utils/Inc/lobby.hpp`. Правила изменения
модуля — `AGENTS.md` рядом; история решений — `docs/adr/`.

## Назначение

Пул фиксированной ёмкости для однотипных сущностей (танки, снаряды):
владеет массивом `T entities[N]` целиком и выдаёт указатели на слоты без
каких-либо аллокаций. «Активность» — окно `items[0..n_active)`; внутри
окна элементы компактны, но порядок их не стабилен (см. `lull()`).

За что НЕ отвечает: заполнение/переконфигурация слота (`respawn` и т.п.
— на совести вызывающего), проверка границ `operator[]`, время жизни
элементов (деструкторы не существуют — слоты переиспользуются
переконфигурацией).

## Вход / Выход

- `activate()` → `T*` нового активного слота (`n_active` растёт) или
  `nullptr`, если пул полон.
- `sleep()` → `T*` хвостового слота без активации («бронь») или
  `nullptr`, если пул полон. Слот остаётся за окном активности, пока не
  последует `activate()`.
- `lull()` → выталкивает элемент под курсором из окна активности;
  вызов предполагается во время итераторного прохода.
- `start()` / `next()` / `is_nEnd()` → итератор по активным;
  `is_nEnd()` — «не конец» (`true`, пока проход не завершён).
- `operator[](i)` → сырой `items[i]`, без проверок.
- `active_n()` / `sleep_n()` → счётчики живых/свободных слотов.

## Пример применения

Реальные call-sites: `Game/Inc/game.hpp:196-199` (спавн), `:326-329`
(выстрел), `:372-377` (lull-проходы). Упрощённо:

```cpp
// Спавн: забронировал → сконфигурировал → активировал
Tank<LcdT>* free_tank = tanks.sleep();
if (!free_tank) return;              // пул полон
free_tank->respawn(pt.x, pt.y, s_i);
tanks.activate();

// Выстрел: сразу активация, nullptr — выстрела не будет
Shell<LcdT>* shell_ready = shells.activate();
if (!shell_ready) return;

// Конец кадра: проход по активным и выталкивание трупов
for (const Shell<LcdT>* s = shells.start(); shells.is_nEnd(); s = shells.next())
  if (!(s->life)) shells.lull();
```

## Предупреждения при использовании

- `sleep()` без последующего `activate()` НЕ активирует слот: элемент
  невидим для проходов и счётчиков. Пара «забронировал → активировал» —
  на совести вызывающего.
- Кадр ДОЛЖЕН дотолкать трупы lull-проходами до конца кадра: `spawn()`
  пересчитывает квоту по side-тегам живых, незалулленный труп задвоит
  бронь.
- После `lull()` следующий `next()` НЕ двигает курсор: на место
  вытолкнутого встаёт хвостовой элемент — следующий `next()` вернёт
  именно его.
- Индексы после `lull()` недостоверны: `lull()` переставляет элементы
  (`std::swap`) — не кэшировать `operator[]` сквозь lull-проходы.
- `operator[]` сырой: индекс ДОЛЖЕН быть `< active_n()` для прохода по
  активным.
