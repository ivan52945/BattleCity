# Utils — пул `Lobby<T, N>`

Контракт использования пула `Lobby<T, N>` (`Utils/Inc/lobby.hpp`).
Правила изменения — `AGENTS.md` рядом.

## Назначение

Пул фиксированной ёмкости для однотипных сущностей (танки, снаряды):
владеет массивом `T entities[N]` целиком и выдаёт указатели на слоты
без аллокаций. «Активность» — окно `items[0..n_active)`; внутри окна
элементы компактны, но порядок элементов не гарантирован (см. `lull()`).

За что НЕ отвечает: заполнение и переконфигурация слота (`respawn` и
подобные — обязанность вызывающего), проверка границ `operator[]`,
время жизни элементов (деструкторы не существуют — слоты
переиспользуются переконфигурацией).

## Вход / Выход

- `activate()` — возвращает `T*` нового активного слота (`n_active`
  растёт) или `nullptr`, если пул полон.
- `sleep()` — возвращает `T*` хвостового слота без активации (резерв)
  или `nullptr`, если пул полон; слот остаётся за окном активности,
  пока не последует `activate()`. Резервы не накапливаются: повторный
  `sleep()` до `activate()` выдаёт тот же хвостовой слот.
- `lull()` — выталкивает элемент под курсором из окна активности;
  вызывается во время итераторного прохода.
- `start()` / `next()` / `is_nEnd()` — итератор по активным;
  `is_nEnd()` — признак продолжения прохода (истинно, пока проход
  не завершён).
- `operator[](i)` — прямой доступ к `items[i]`, без проверок границ.
- `active_n()` / `sleep_n()` — счётчики активных и свободных слотов.

## Пример применения

Реальные call-sites: `Game/Inc/game.hpp:196-199` (спавн), `:326-329`
(выстрел), `:372-377` (lull-проходы). Упрощённо:

```cpp
// Спавн: резерв слота → конфигурация → активация
Tank<LcdT>* free_tank = tanks.sleep();
if (!free_tank) return;              // пул полон
free_tank->respawn(pt.x, pt.y, s_i);
tanks.activate();

// Выстрел: активация сразу; nullptr — выстрела не будет
Shell<LcdT>* shell_ready = shells.activate();
if (!shell_ready) return;

// Конец кадра: проход по активным и выталкивание уничтоженных
for (const Shell<LcdT>* s = shells.start(); shells.is_nEnd(); s = shells.next())
  if (!(s->life)) shells.lull();
```

## Предупреждения при использовании

- `sleep()` без последующего `activate()` не активирует слот: элемент
  невидим для проходов и счётчиков. Пара «резерв → активация» —
  обязанность вызывающего.
- Кадр обязан вытолкнуть уничтоженные сущности lull-проходами до конца
  кадра: `spawn()` пересчитывает квоту по side-тегам живых — мёртвый
  элемент, оставшийся в окне, будет забронирован повторно.
- `lull()` на пустом окне активности не вызывается — контроль пустоты
  на стороне вызывающего.
- После `lull()` следующий `next()` не перемещает курсор: на место
  вытолкнутого встаёт хвостовой элемент — следующий `next()` вернёт
  именно его.
- Индексы после `lull()` недостоверны: `lull()` переставляет элементы
  (`std::swap`) — сохранённые значения `operator[]` после lull-прохода
  недействительны.
- `operator[]` без проверок границ: индекс для прохода по активным
  должен быть меньше `active_n()`.
