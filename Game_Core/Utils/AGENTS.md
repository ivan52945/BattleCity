# Utils — пул Lobby<T, N>

`lobby.hpp` — переиспользуемый пул значений: фиксированный
`T entities[N]` + параллельный `T* items[N]`; «активность» — окно
`items[0..n_active)`. Слоты переиспользуются переконфигурацией живого
объекта (`respawn`/`get_out`), не реконструкцией — поэтому деструкторы
элементов не нужны и не существуют.

Разделение ролей: контракт использования (вход/выход, пример, ловушки
потребителя) — `README.md` рядом; здесь — правила изменения.

## Инварианты реализации

- Guard полного пула — `n_active >= N` в `activate()`/`sleep()`:
  наивный `>` читал `items[N]` — фикс пункта I, не ослаблять.
- `lull()` — `n_active -= 1` + `std::swap(items[current],
  items[n_active])`; флаг `is_sleep` гасит один шаг `next()`, чтобы
  элемент, вставший на место вытолкнутого, не выпал из прохода.
- Пул живёт значением внутри `GameT` на стеке `main()`: рост пула
  двигает stack-usage, НЕ .bss/.data.
- sizeof (ARM-ABI): `Lobby<Tank,8>` = 716 Б, `Lobby<Shell,96>` =
  4 620 Б — см. `docs/metrics.md`.

## Не трогать

- `std::swap` в lull — не возвращать XOR-трюк (хрупок при алиасинге).
- Размер шелового пула 96 → `cfg::shell_pool` — оформленный пункт P
  (−3 456 Б стека при 24), вместе со static_assert против
  `units_per_side`.
